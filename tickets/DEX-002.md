# DEX-002 - Screened Free DEX OHLCV Acquisition

**Priority:** P0
**Status:** ACCEPTED
**Dependencies:** DATA-007 (ACCEPTED), RAW-001 (ACCEPTED), MAN-001 (ACCEPTED)
**Layer:** acquisition / ingest / catalog
**Architecture:** provider capabilities are separated; exact raw responses and immutable full-snapshot publication. **No Birdeye OHLCV. No LIVE.**

## Objective

Publish a deterministic, resumable DEX daily-OHLCV snapshot for a screened pool set
without inventing candles, losing history on incremental refresh, or accepting pools
whose liquidity and volume were not actually observed.

This specification supersedes the original DEX-002 implementation and the DEX-002
portion of the `7cf17d0` DATA-010 rework.

## Architectural decisions

1. **Provider capabilities are explicit.** A provider may supply interval OHLCV,
   authoritative screening metrics, or context. Those capabilities are independent.
2. **GeckoTerminal is the only currently authorized OHLCV source.** DexScreener
   current-price/24h snapshots are screening evidence, not candles. DefiLlama token
   prices are context only. Neither may create or gap-fill OHLCV rows.
3. **Screening is fail-closed.** A pool passes only from a valid authoritative
   observation containing finite liquidity and 24h volume at or above both configured
   thresholds. Missing metrics, provider errors, and context-only responses cannot pass.
4. **Incremental refresh publishes a full canonical snapshot.** A delta must never
   replace prior history as the latest dataset.
5. **DEX death is not declared here.** This ticket publishes dated screening/activity
   observations. DEX-003 owns birth/death and point-in-time universe semantics.

## Required implementation

### Provider and screening contracts

- Replace untyped `dict` screening outcomes with a narrow typed result containing:
  provider, capability, observation time, liquidity, volume, status, and reason.
- Status must distinguish `PASS`, `REJECT`, `UNAVAILABLE`, and `CONTEXT_ONLY`.
- DexScreener is the authoritative screening source for this ticket.
- Default thresholds are `min_liquidity_usd=50_000` and
  `min_volume_24h_usd=10_000`; both remain configurable and are fingerprinted.
- A valid below-threshold observation is `REJECT`. Missing or failed evidence is
  `UNAVAILABLE` and remains retryable; it is not a death observation.
- The abstract/default provider path must fail closed. DefiLlama can never make a
  pool pass. All configured providers are still called for auditable context.

### Genuine OHLCV only

- GeckoTerminal rows must come from its interval OHLCV endpoint.
- Remove/disable DexScreener synthetic rows that set open/high/low/close to a current
  snapshot price and attach 24h volume to one timestamp.
- Validate UTC timestamps, requested range, interval alignment, finite values,
  `low <= open/close <= high`, nonnegative volume, uniqueness, and deterministic order.
- Detect interval gaps. No silent or synthetic gap filling is permitted.
- Pool identity is `(chain, canonical_pool_address)`: lowercase valid EVM addresses;
  preserve case-sensitive non-EVM addresses. Chain is part of every dedupe/watermark key.

### Raw lineage and failures

- Preserve every controlling HTTP response with `RawObjectWriter` before decoding,
  including screening, OHLCV, and HTTP/protocol error bodies.
- Record request, acquisition ID/time, provider, chain, pool, range, and raw object ID.
- Published dataset dependencies must contain every controlling raw object and the
  prior canonical dataset when an incremental snapshot is merged.
- Transport failures with no body must still leave failed-acquisition evidence.
- Tests must use injected transports; hidden network access is forbidden.

### Resume and publication

- Watermarks are keyed by provider, chain, and canonical pool identity.
- Advance only to the last contiguous validated row that was successfully published.
- Never advance on empty results, errors, unresolved gaps, or publication failure.
- Persist watermarks atomically and retain unrelated/provider shards.
- Merge prior canonical rows with newly acquired rows, then deterministically dedupe
  by `(chain, pool_address, timestamp)` before publishing the new full snapshot.
- Repeating the same run must be idempotent. A no-data/error run must not replace the
  latest canonical dataset.
- Use the real code commit and canonical configuration hash; no placeholders.
- A zero-row or unresolved-quality run exits nonzero and publishes no PASS dataset.

### Evidence report

Publish `research/sprint_004/44_DEX002_REWORK_REPORT.json` with:

- pinned end time and effective configuration;
- candidate, passed, rejected, and unavailable pools as separate collections;
- exact screening evidence and reasons;
- per-pool/provider row counts, coverage, gaps, retries, and rate-limit incidents;
- raw dependency counts and prior-dataset dependency, when applicable;
- watermark before/after values;
- full-snapshot row count and catalog reconciliation;
- `live_eligible: false`.

Mark `37_DEX_MULTI_PROVIDER_FANOUT.json` as superseded prototype evidence. It has no
research or canonical-data authority because it contains fail-open screening evidence.

## Required tests

- Context-only and missing-metric results cannot pass screening.
- A valid authoritative pass/reject uses both thresholds exactly.
- Provider errors produce `UNAVAILABLE`, remain retryable, and do not advance watermarks.
- DexScreener cannot emit OHLCV rows.
- Invalid bars, duplicates, out-of-range rows, and gaps fail closed.
- Cross-chain equal-looking addresses do not collide; EVM and non-EVM casing rules hold.
- Exact response bytes and failure attempts are preserved before decode/raise.
- Primary-only merge, prior-snapshot merge, deterministic dedupe, and idempotent rerun.
- Empty/error/publication-failure paths preserve prior canonical data and watermarks.
- Actual runner publication and catalog reconciliation; no reimplementation in tests.
- No live network in CI.

## Acceptance criteria

- [x] Provider capability separation is enforced.
- [x] Screening is metric-bearing and fail-closed at the configured thresholds.
- [x] Every OHLCV row comes from a genuine interval-bar response.
- [x] Raw acquisition lineage is complete and replay/audit capable.
- [x] Resume is retry-safe and watermarks advance only after successful publication.
- [x] Latest publication is a complete canonical snapshot, never a delta replacement.
- [x] Controlled real run publishes the rework report with catalog reconciliation.
- [x] Ticket tests pass, scoped Ruff passes, full suite has no new failures, and repo control passes.
