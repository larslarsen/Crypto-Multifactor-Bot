# DEX-003 — DEX Survivorship Universe (Birth + Death)

**Priority:** P1
**Status:** READY
**Dependencies:** DEX-002 (ACCEPTED), UNIVERSE-004 (ACCEPTED), DATA-007 (ACCEPTED)
**Layer:** universe / dex
**Architecture:** birth dates from DexScreener/GeckoTerminal metadata; death from OHLCV liquidity thresholds; forward listings from Birdeye. **No Birdeye OHLCV. No LIVE.**

## Objective

Build a survivorship-aware DEX universe: birth dates for all pools (historical + forward), death dates via liquidity/volume thresholds, so experiments can run point-in-time without survivorship bias.

## Current State

- DexScreener returns `pairCreatedAt` (epoch ms) for every pool
- GeckoTerminal returns `pool_created_at` (ISO timestamp) for every pool
- Both are free, no key required
- Death defined per UNIVERSE-004: liquidity + volume below thresholds for 7 days
- Forward listings from Birdeye `new_listing` events
- No survivorship data currently collected — pools are just OHLCV streams without birth/death metadata

## Scope

### In scope

1. **Birth date resolution** — For each pool in the fan-out universe, query DexScreener or GeckoTerminal pool metadata once and extract `pairCreatedAt` / `pool_created_at`. Store as the pool's birth date in `ref_instrument`.

2. **Cross-source verification** — Compare DexScreener vs GeckoTerminal birth dates for the same pool. If they disagree by >24h, flag for manual review. Accept the earliest of the two as the authoritative proxy birth.

3. **Death date detection** — Per UNIVERSE-004 pragmatic death: when a pool's daily liquidity AND volume stay below configurable thresholds (`--min-liquidity 50000 --min-volume 10000`) for 7 consecutive days, mark as dead with the last day above threshold as the death date. Re-check daily on incremental refresh.

4. **Coverage estimation** — Probe the number of pools DexScreener tracks (via token search) to understand the total DEX pool universe size. GeckoTerminal's 180-day OHLCV limit means pools older than 180 days with no recent activity may be invisible — DexScreener's metadata endpoint covers this gap.

5. **Catalog tables** — Publish `ref_instrument` (pool_address, chain, birth_date) and `ref_listing_event` (pool_address, event_type=birth/death, event_date, source) in the catalog.

6. **Report** `research/sprint_004/51_DEX_SURVIVORSHIP.json` with:
   - pools with resolved birth dates
   - cross-source verification results
   - pools flagged as dead with death dates
   - pools with unresolvable birth (document why)
   - estimated total DEX pool universe size

### Out of scope

- OHLCV backfill (DATA-010)
- CEX survivorship (UNIVERSE-005)
- Birdeye OHLCV (permanent constraint)
- LIVE / factor research
- On-chain birth verification (free metadata is sufficient proxy)
